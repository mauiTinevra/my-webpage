How this was made

The brief: a four-chair barbershop near Camelback Road where a customer can see the next open chair and book it. The site had to look like an enamel shop sign over a tiled floor, and prove a complete booking flow with real time logic and no server.

Palette and type

Cream enamel#f4efe3, about 60 percent. Text on it reads at 14.2 to 1.
Oxblood#6b1f2a, about 30 percent. Cream on it reads at 9.9 to 1.
Brass#c79a3b, about 10 percent. Pinstripes, screws, the open lamp. Never text on cream.
FloorBlack #1a1614 and cream, in the tile band only.

Brass on cream is only 2.3 to 1, so brass never carries words on the cream ground. Where gold lettering was wanted, on the sign and the price board, a lighter brass sits on oxblood at 6.5 to 1. Chair status is always written out, so color is never the only signal.

Alfa Slab One

The sign face. One weight, so hierarchy comes from size and from a stepped brass block shade built out of six stacked text shadows.

Work Sans

Everything else, as one variable font file. Figures are set tabular so times line up down the board.

Both are self-hosted Latin subsets from the Fontsource packages. The barber pole, the sign, the screws with their chipped enamel, the checkerboard and the ticket stub are CSS. The chairs, tools and map are SVG written by hand.

The chair board

Three small pieces do the work. First, the clock. The page never trusts the visitor's own time zone. It asks Intl.DateTimeFormat for the wall-clock parts of the present moment in America/Phoenix and reduces them to a calendar day and minutes after midnight. Phoenix does not move its clocks in summer, and the browser's zone data already knows that.

var partsFmt = new Intl.DateTimeFormat('en-US', {
  timeZone: 'America/Phoenix', hourCycle: 'h23',
  year: 'numeric', month: 'numeric', day: 'numeric',
  hour: 'numeric', minute: 'numeric'
});

function phoenixNow() {
  var p = wallParts(new Date(Date.now() + skew));
  var key = dayKey(p.year, p.month, p.day);      // "2026-11-19"
  return { key: key, mins: p.hour * 60 + p.minute, dow: dowOf(key) };
}

Second, the invented schedule. Each barber has shifts and a lunch. Other customers' appointments come from a small seeded random generator, and the seed is the date plus the chair number. A given Thursday therefore looks the same on every load, which is what lets a saved booking survive a reload without ever landing on top of somebody else.

Third, the status. For each chair the page walks that day's taken blocks and names what is happening this minute.

for (var i = 0; i < busy.length; i++) {
  var x = busy[i];
  if (now.mins >= x.s && now.mins < x.e) {
    if (x.type === 'lunch') return { kind: 'away', line: 'At lunch until ' + clock(x.e) };
    if (x.type === 'mine')  return { kind: 'busy', line: 'Your cut, until ' + clock(x.e) };
    return { kind: 'busy', line: 'Cutting until ' + clock(x.e) };
  }
  if (x.s > now.mins && !upcoming) upcoming = x;
}
var until = upcoming ? upcoming.s : plan.shift[1];
// Less than a quarter of an hour is not an open chair, it is a barber sweeping up.
if (until - now.mins < 15) return { kind: 'away', line: 'Setting up for the ' + clock(until) };
return { kind: 'open', line: 'Open now, until ' + clock(until) };

Open times are every start on the 20-minute grid where the chosen service fits between taken blocks, plus one off-grid start a few minutes from now when a chair is empty this minute. The board re-reads the clock on each minute and when the tab comes back into view, and it re-checks the chosen time at the moment of booking. When the shop is closed the chairs say so, the first screen names the next opening, and the day picker starts on the next open day.

The booking is one small object in sessionStorage, wrapped in try and catch so a browser that blocks storage still books for the life of the page. Change reopens the same form with the old time freed and marked. Cancel asks once, then gives the time back. Every control is a real button or radio input, results are announced through a live region, and focus moves to the ticket when it prints.

Because the shop is closed for much of the day, the address accepts a pretend time. These open the site at three moments:

A busy Thursday, 3:22 PM Wednesday lunch, 1:10 PM Closed, Sunday night

Three critique passes

  1. Pass one found broken basics. The word "Camelback" ran off the right edge of the sign on desktop, a font preload threw a console error when the page was opened from disk, the service buttons were uneven heights, and the invented schedule was so full that a fade had one opening all afternoon. A chair could read "open now" while its first bookable time was two hours off. Fixed: the sign lettering is sized from the sign's own width with a container query, the preload is gone, the schedule is lighter, and an empty chair now offers a start a few minutes from now. Upgrade: the sign lettering got a proper stepped block shade in place of a single offset shadow.
  2. Pass two looked at the flow in use. After booking, the board still said "Pick a chair". The chair holding your booking said it was "setting up" for a stranger. Changing a booking stacked two notices saying the same thing. On a phone the day picker ran off the side and the barber cards were two cramped columns. Fixed: the heading becomes "The shop right now", your chair says "Ready for you", repeated messages go to a screen-reader-only region, days sit in a three-column grid, and barbers stack with their tool beside them. Upgrade: a day strip under each chair shows taken time, lunch and a brass tick for now, so the status line has something to point at.
  3. Pass three was about finish. The price board had ruled lines that ended at different heights in each column and left the word "minutes" alone on a line. The map label sat on top of a street name. Two links were shorter than 44 pixels. Fixed: prices use dotted leaders and balanced descriptions, the label moved onto its own block with a leader line, and the links grew. Upgrade: the screws on both signs got chipped enamel around them, black steel with a rust edge, drawn with one irregular radial gradient each.

One honest limitation

Nothing leaves the browser. The other customers are generated, and your booking lives in one tab's session storage, so two visitors could both book Tino at 4:00 and neither would know. A real shop needs a small server that owns the calendar, confirms a slot only once, and sends a text reminder. The time logic, the flow and the ticket would carry over as they are.

The brief asked for the guide link to point at the folder. It points at guide/index.html instead, so it also works when the site is opened straight from disk.
